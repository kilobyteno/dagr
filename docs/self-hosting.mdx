# Self-hosting Dagr

Dagr is built to run on your infrastructure with no required cloud SaaS.

## One-command deploy

From the repository root:

```bash
make compose-up
```

### Services

| Service | Port | Purpose |
| --- | --- | --- |
| Dagr API | `8080` | HTTP API (`/api/v1/*`) |
| Postgres | `5433` (host) → `5432` (container) | Primary data store |
| Redis | `6379` | Pub/sub, cache, asynq queues |
| MinIO | `9000` (API), `9001` (console) | File attachments |

Default credentials are for local development only. Change them before any shared or production deployment.

## Configuration

See `deploy/.env.example` in the repository. Key variables:

- `HTTP_ADDR`: listen address (default `:8080`)
- `DATABASE_URL`: Postgres connection string
- `REDIS_URL`: Redis connection string
- Password policy (returned on `GET /api/v1/public/config` for clients):
  - `PASSWORD_MIN_LENGTH` (default `12`)
  - `PASSWORD_REQUIRE_UPPERCASE` (default `true`)
  - `PASSWORD_REQUIRE_LOWERCASE` (default `true`)
  - `PASSWORD_REQUIRE_NUMBER` (default `true`)
  - `PASSWORD_REQUIRE_SYMBOL` (default `false`)
- `SESSION_TTL`: opaque session lifetime as a Go duration (default `720h`, 30 days)
- `PUBLIC_BASE_URL`: web origin for invite accept and email verification links (default `http://localhost:5173`)
- Transactional email (delivered by the worker via asynq `email:send`):
  - `EMAIL_PROVIDER`: `log` (default), `smtp`, or `lettermint`
  - `EMAIL_FROM`: sender address (required for `smtp` and `lettermint`)
  - `SMTP_HOST`, `SMTP_PORT` (default `587`), `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_TLS` (default `true`)
  - `LETTERMINT_API_TOKEN`, optional `LETTERMINT_BASE_URL`
- `S3_*`: MinIO / S3-compatible object storage
- `DEPLOYMENT_MODE`: `selfhosted` (default) or `cloud`. Self-hosted never enables payment plans.
- Cloud-only Mollie keys (`MOLLIE_API_KEY`, `MOLLIE_PROFILE_ID`, `MOLLIE_WEBHOOK_URL`) must stay unset here. See [Cloud billing](/cloud).

Run `make worker-run` so scheduled messages, link unfurls, and outbound email (invites and verification) are processed. With `EMAIL_PROVIDER=log`, messages are written to the worker logs instead of being delivered.

Compose runs `dagr-migrate up` before starting the API. For local API development with auto-reload:

```bash
make compose-infra   # Postgres, Redis, MinIO only
make migrate-up
make run-watch       # Air watches .go files and restarts the server
```

One-shot without a watcher: `make run`. Avoid running the Compose `dagr` service and `run-watch` at the same time (both use `:8080`).

### Auth API

| Method | Path | Notes |
| --- | --- | --- |
| `POST` | `/api/v1/auth/signup` | `{ email, password, displayName }` → token + user (unverified; queues verification email) |
| `POST` | `/api/v1/auth/login` | `{ email, password }` → token + user |
| `POST` | `/api/v1/auth/verify-email` | `{ token }` from the verification link (public) |
| `POST` | `/api/v1/auth/logout` | Bearer token required |
| `GET` | `/api/v1/me` | Bearer token required; includes `emailVerified` |
| `POST` | `/api/v1/me/email/resend-verification` | Resend verification email (rate limited) |
| `PATCH` | `/api/v1/me` | `{ displayName, notificationLevel }` (`all` \| `mentions` \| `nothing`; account ceiling for all notifications) |

Signup does not create a workspace. Clients create one via the workspaces API (seeds `#general`). New accounts start unverified and receive a soft warning in the web UI until they open the verification link. Existing accounts are grandfathered as verified when you migrate.

### Workspaces API

Bearer token required for all routes.

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/api/v1/workspaces` | Caller's memberships (`id`, `name`, `slug`, `role`) |
| `POST` | `/api/v1/workspaces` | `{ name }` → workspace + seeded `#general` channel |
| `GET` | `/api/v1/workspaces/{workspaceID}` | Detail if member |
| `PATCH` | `/api/v1/workspaces/{workspaceID}` | `{ name }` rename (owner/admin); updates slug |
| `DELETE` | `/api/v1/workspaces/{workspaceID}` | Delete workspace (owner/admin) |
| `GET` | `/api/v1/workspaces/{workspaceID}/me` | Caller's membership (`handle`, `displayName`, `role`) |
| `PATCH` | `/api/v1/workspaces/{workspaceID}/me` | `{ handle }` unique per workspace |
| `GET` | `/api/v1/workspaces/{workspaceID}/members` | Members with handles, roles, and external origin fields |
| `PATCH` | `/api/v1/workspaces/{workspaceID}/members/{userID}` | `{ role }` (owner/admin; cannot demote last owner) |
| `DELETE` | `/api/v1/workspaces/{workspaceID}/members/{userID}` | Remove member (not self; not last owner) |
| `POST` | `/api/v1/workspaces/{workspaceID}/leave` | Leave workspace (sole owner must transfer first) |
| `POST` | `/api/v1/workspaces/{workspaceID}/transfer-ownership` | `{ userId }` (current owner only) |
| `DELETE` | `/api/v1/workspaces/{workspaceID}/invites/{inviteID}` | Revoke pending invite |
| `GET` | `/api/v1/workspaces/{workspaceID}/channels` | Accessible channels only (private requires membership) |
| `POST` | `/api/v1/workspaces/{workspaceID}/channels` | `{ name, isPrivate, topic? }` |
| `PATCH` | `/api/v1/channels/{channelID}` | `{ name?, topic?, isPrivate }` (making private seeds updater/creator as members) |
| `DELETE` | `/api/v1/channels/{channelID}` | Hard delete |
| `POST` | `/api/v1/channels/{channelID}/members` | `{ email }` (private channels) |
| `DELETE` | `/api/v1/channels/{channelID}/members/{userID}` | Remove private member |
| `GET` | `/api/v1/channels/{channelID}/notification-settings` | Personal level: `all` \| `mentions` (default) \| `nothing` |
| `PUT` | `/api/v1/channels/{channelID}/notification-settings` | `{ level }` |
| `POST` | `/api/v1/workspaces/{workspaceID}/invites` | `{ email, role? }` → `added` or pending `invited` |
| `GET` | `/api/v1/workspaces/{workspaceID}/invites` | Pending invites (owner/admin) |
| `POST` | `/api/v1/invites/{token}/accept` | Join if email matches session user |
| `GET` | `/api/v1/channels/{channelID}/messages` | `?before=&beforeId=&limit=` (includes `linkPreviews` when present) |
| `POST` | `/api/v1/channels/{channelID}/messages` | `{ body }` (queues link unfurls for http(s) URLs; worker fills `linkPreviews`) |
| `POST` | `/api/v1/channels/{channelID}/scheduled-messages` | `{ body, sendAt }` |
| `GET` | `/api/v1/channels/{channelID}/scheduled-messages` | Own pending (+ admin) |
| `DELETE` | `/api/v1/scheduled-messages/{id}` | Cancel pending |
| `GET` | `/api/v1/notifications` | `?filter=all\|unread\|mentions&limit=` → items + `unreadCount` |
| `POST` | `/api/v1/notifications/{id}/read` | Mark one read |
| `POST` | `/api/v1/notifications/read-all` | Mark all read |

Public channels are readable by any workspace member. Private channels require `channel_members` (creator is added automatically). Run `make worker-run` so due scheduled messages, link unfurls, and outbound email are processed (Redis required).

Notifications are created for `@handle` mentions in channel messages (workspace unique handle preferred; display name still matches as a fallback), private channel membership adds, immediate workspace adds, and workspace joins (owners/admins notified on accept).

Set `PUBLIC_BASE_URL` (default `http://localhost:5173`) for invite accept and email verification links.

### Workspace domains

Owner/admin only for mutations. Members may list domains.

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/api/v1/workspaces/{workspaceID}/domains` | List claims + DNS TXT host/value |
| `POST` | `/api/v1/workspaces/{workspaceID}/domains` | `{ domain }` → pending claim + token |
| `POST` | `/api/v1/workspaces/{workspaceID}/domains/{domainID}/verify` | Lookup `_dagr-challenge.<domain>` TXT |
| `PATCH` | `/api/v1/workspaces/{workspaceID}/domains/{domainID}` | `{ autoJoin }` (verified only) |
| `DELETE` | `/api/v1/workspaces/{workspaceID}/domains/{domainID}` | Remove claim |

TXT value format: `dagr-domain-verification=<token>`. A domain may be verified by at most one workspace. Public email providers (for example `gmail.com`) are rejected. When `autoJoin` is enabled, new signups whose email matches that domain become `member` of the workspace.

### Billing API (Cloud only)

Self-hosted servers report `billingEnabled: false` on public config. Checkout routes then return `billing_disabled`.

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/api/v1/workspaces/{workspaceID}/billing` | Plan, seats, entitlements |
| `POST` | `/api/v1/workspaces/{workspaceID}/billing/checkout` | `{ interval: monthly\|yearly }` → Mollie `checkoutUrl` |
| `POST` | `/api/v1/workspaces/{workspaceID}/billing/cancel` | Keep Pro until period end |
| `POST` | `/api/v1/workspaces/{workspaceID}/billing/resume` | Resume a cancelled Pro plan |
| `POST` | `/api/v1/billing/webhooks/mollie` | Public Mollie webhook (`id` form field) |

## Verify

```bash
curl -s http://localhost:8080/api/v1/health
# {"status":"ok"}

curl -s http://localhost:8080/api/v1/public/config
```

## Stop

```bash
make compose-down
```

Data volumes (`postgres_data`, `redis_data`, `minio_data`) persist until you remove them with:

```bash
docker compose -f deploy/docker-compose.yml down -v
```

The desktop client may sign into multiple servers at once and merge workspace rails and notifications locally. Cross-server Connect federation is deferred.

## Production notes

- Replace default passwords and keys.
- Terminate TLS in front of the API (reverse proxy or load balancer).
- Back up Postgres and MinIO volumes.
- Kubernetes / Helm charts are planned later; Compose is the supported path today.
