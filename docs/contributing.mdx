# Contributing to Dagr

Thank you for helping build a privacy-centric, self-hostable team chat.

## Development setup

1. Install Go 1.24 or newer.
2. Clone the repository.
3. Install dependencies: `make tidy`
4. Start dependencies: `make compose-infra` (Postgres, Redis, MinIO)
5. Apply migrations: `make migrate-up`
6. Run the API with reload: `make run-watch` (or `make run` once)

`make run-watch` uses [Air](https://github.com/air-verse/air) via `.air.toml`. Full stack in Docker: `make compose-up`.

## Desktop app (development)

The Electron app lives in `web/`. Users should follow [Quick start](/quickstart) and the [desktop guides](/desktop). This section is for changing the client.

You need Node.js 20+, pnpm, and a [shadcnblocks](https://www.shadcnblocks.com) Pro key in `web/.env`:

```bash
SHADCNBLOCKS_API_KEY=sk_live_your_key
```

```bash
make web-install
make web-dev
```

`make web-dev-2` opens a second window with its own session (invites, DMs, notifications).

Build-time defaults: `VITE_DAGR_CLOUD_URL` (Cloud tab) and `VITE_DAGR_SELF_HOSTED_URL` (suggested self-hosted URL). See `web/.env.example`. Keep the self-hosted default in sync with `HTTP_ADDR`.

Typecheck and build the renderer with `make web-build`. Package installers with `make web-package` (runs electron-builder for your current platform).

## Releasing the desktop app

GitHub Actions packages macOS (universal DMG) and Windows (NSIS) when you push a version tag.

1. Set the version you want in `web/package.json`, or let the workflow take it from the tag (`v0.1.0` becomes `0.1.0`).
2. Push the tag: `git tag v0.1.0 && git push origin v0.1.0`.
3. Wait for both jobs on the **Release desktop** workflow.
4. Open the draft GitHub Release, check that `Dagr_<version>.dmg` and `Dagr_<version>.exe` are attached, then publish it.

The download site and the in-app update checker only see published releases, not drafts. Builds are unsigned in this pass.

## Download website

The public download page lives in `website/`. It is a Next.js app you can host in Docker.

```bash
make website-install
make website-dev
```

Build a production image from `website/Dockerfile`. Do not add it to the API Compose stack.

## Documentation

Docs are authored as MDX under `docs/` and configured by root `docs.json` for [docs.page](https://docs.page).

Preview locally:

```bash
make docs-preview
```

Check links and MDX:

```bash
make docs-check
```

## Workflow

- Keep changes focused and minimal.
- Prefer British English in user-facing docs.
- API routes belong under `/api/v1/`.
- Self-hosting must stay one-command via Docker Compose where possible.
- Do not introduce required external SaaS dependencies.

## Checks

```bash
make build
make test
make lint
```

## Pull requests

- Describe the problem and the approach.
- Link related issues when applicable.
- Include a short test plan for behavioural changes.
